ShadowLink Technical Overview

A Comprehensive Presentation & Architecture Guide

Project Executive Summary

ShadowLink is a secure, real-time, disappearing-message web application optimized as a Progressive Web App (PWA) for mobile devices. It is built to facilitate instant, zero-trace communications among private teams.

Unlike standard messengers, ShadowLink treats privacy and data sanitation as hard code constraints. It hides real-world identity mappings behind secret codenames on the server, destroys message history dynamically from all memory registers exactly 10 seconds after a message is read, and restricts reading capabilities to mobile devices to secure visual boundaries.

Technology Stack Details

Frontend UI Stack

Built using HTML5, Vanilla CSS3 (with dark-mode glassmorphic styling), and Vanilla ES6 Javascript. The interface uses customized responsive layouts to adapt instantly to different screen sizes without heavy UI frameworks.

Real-time Server Stack

Uses a Node.js and Express backend server coupled with Socket.io. This framework establishes immediate, bidirectional persistent TCP connections to coordinate registrations, online states, and messages instantly.

Web Push Notification API

Powered by the Web-Push Protocol (VAPID). The server connects directly to Google FCM / Apple APNS push gateways to wake up mobile browser service workers and render notification banners even when the device is locked or the app is closed.

Storage Sandbox

A JSON database (db.json) handles persistent user PIN allocations and Web Push device subscription keys. Client-side caching utilizes encrypted LocalStorage, strictly sandboxed to individual users to prevent cross-user device snooping.

Key Technical Concepts & Design Patterns

  • Identity Abstraction Model

    Real-world user mappings are locked inside server-side configuration memory. The client application only displays and operates on secret codenames (e.g. Shadow, Orion, Ghost). There is no mechanism for standard clients to fetch another user's true identity from the API.

  • Double-Gated Self-Destruct Lifecycle

    Messages exist in an "Unopened" state. Opening triggers a client-side ticking circle animation countdown (Web Audio pop/sweep alerts) and alerts the backend server. The server schedules an immediate 10-second timer, sweeping the message text in RAM and replacing it with "• Message self-destructed •". This guarantees no trace remains in RAM or file registers.

  • Dynamic Push & Foreground Filtering

    Because mobile OS kernels close WebSocket streams when backgrounded, the server immediately triggers a Web Push notification for incoming messages. The mobile PWA's Service Worker receives the push event and dynamically detects window status. If the app is active in the foreground, it suppresses the push banner (to avoid duplicates); if backgrounded, it fires the alert immediately.

  • Hardware & Inspector Hardening

    The app prevents snooping and screenshot captures using three layers:
    • Hold-To-View: Users must actively press and hold their finger on the message block to reveal text. Lifting the finger or attempting a screenshot gesture disrupts the touch input, immediately hiding the text.
    • DevTools Blocker: Disables right-clicks (Context Menu) and captures key combinations for developer inspectors (F12, Cmd+Opt+I, Ctrl+Shift+I). An ongoing loop measures window dimension alterations and debugger delays, blocking the DOM if developer options are opened.
    • Blur Overlay & CSS Print Blocks: Blurs the application body dynamically on focus loss (iOS/Android application switcher views) and uses CSS @media print to completely blank out the screen during print or screen capture commands.

How to Demo / Explain This Project

Use the following sequence to showcase the system to examiners or clients:

1

Initial Verification Form

Show the main login page. Explain that standard selection cards have been removed for safety. Enter your Codename (e.g., Shadow) and your 4-digit PIN. If it's a first-time login, explain how it asks to secure the account using that PIN.

2

Demonstrate Mobile Lock Constraints

Open the app on a computer and try to open a message. Show that the web app alerts you that reading disappearing messages is restricted to mobile screens only for security. Open the same link on your phone (or resize the browser view) to proceed.

3

Showcase Hold-To-View & Self-Destruction

Open a chat and send a message. Tap to open it on the receiver side. Hold your finger down on the card to read the text. Explain that lifting your finger instantly blurs and hides the content, protecting against physical screen grabs.

4

Verify Background Notification Delivery

Close the app on the receiver's mobile phone (or turn off the phone screen). Send a message from the sender's device. Show that the receiver's phone screen wakes up, vibrates strongly, and shows the notification banner. Tap it to directly focus and load the chat window.
